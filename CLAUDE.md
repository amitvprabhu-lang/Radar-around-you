# Radar Around You: instructions for Claude Code

A free, global, real-time 3D web tool: satellites and the ISS above you, the sky tonight, quakes under you, hazards around you. Personal side project, budget about 500 rupees a month, aiming to be the most helpful astronomy resource and to rank in search. Read `docs/handoff.md` first: it holds the current state, what is done, what is open and what is unverified.

## How the owner wants work done (standing rules)
- Plain, human tone. No em dashes and no emoji, in chat, code comments, docs and commit messages.
- Never state a guess as a fact. Flag any number you are not sure of and say how to verify it. Never invent sources, URLs, function names or API syntax; if unsure, say so and check the current documentation.
- Data must come from the source feeds, not from model memory. Every figure shown to users needs a verified source recorded in `docs/` (see `docs/star-sources.md` for the pattern: what was read, when, and what is NOT CONFIRMED).
- Ask a clarifying question instead of assuming, and state the plan before building.
- Code follows best practice, is unit tested and regression tested, and must not break other code. Run the whole test set before committing.
- Push only after the browser tests pass. Commit messages end with the attribution lines the harness gives.
- Never ask for, accept or store passwords. Tokens and secrets never go in the repository (`hosting/radar-config.php` is ignored on purpose). The GitHub token for the server must be fine-grained, one repository, Actions read and write only.

First time on a machine: `npm ci`, then `npx playwright install chromium` (the harness uses the project's own Playwright and falls back to the cloud container's copy). The browser suites take roughly 10 to 15 minutes each on a software renderer. Delete old output before a run, never run two suites at once, and close other heavy programs first: on this Mac a load average above about 10 made pages take over 60 seconds to start and failed the suite at its 60 second waits. Test pages must be closed when their checks are done, because open pages keep drawing and starve the next one.

## Working here
- Local folder is `/Users/Amit/Radar Near You/Radar-around-you`. The space in the name is why paths in scripts must come from `fileURLToPath`, not `new URL(...).pathname` (fixed in the files that had it).
- `gh` is logged in on the owner's Mac (HTTPS, scopes repo, workflow, read:org, gist). It can start and read Actions runs. Commits in this repository use the owner's GitHub no-reply address as author, set for this repository only.
- Browser-pane and Chrome sessions are not the same login as `gh`: being signed in to GitHub in a browser does not let git push.

## Layout
`src/` app (three.js, bundled by esbuild); `site/` content-page generator (`SITE_URL`, `SITE_NOINDEX`); `pipeline/` Python collector; `hosting/` PHP glue for Hostinger (`pull.php`, `trigger.php`); `test/`, `e2e*.mjs`, `harness.mjs` tests; `docs/` source verification records and hosting notes; `public/` data files the app loads. `site/satcount.mjs`, `site/pages-satcount.mjs` and `site/build-live.mjs` make the live satellite count page (see `docs/superpowers/specs/2026-10-05-satellite-count-page-design.md`); GitHub builds it into the data branch's pages/ folder and `hosting/pull.php --pages-dest` copies it to the site. `site/satcountry.mjs`, `site/svgmap.mjs` and `site/pages-country.mjs` make the satellites by country hub and its five country pages, built beside the count page by the same `build-live.mjs` (see `docs/superpowers/specs/2026-10-05-satellites-by-country-design.md` and `docs/satcountry-sources.md`); the server's `hosting/lib.php` must be the 2026-10-05 version or later to copy them. `site/hazard.mjs` (summaries with freshness checks and guards), `site/pages-hazard.mjs` and `site/livepages.mjs` (the one list of every live page) make the five live hazard pages (`/earthquakes-today/`, `/aurora-tonight/`, `/asteroid-close-approaches/`, `/tropical-storms-now/`, `/wildfires-today/`) and the `/right-now/` hub, built by the same `build-live.mjs`, each page on its own (see `docs/superpowers/specs/2026-10-06-live-hazard-pages-design.md` and `docs/hazard-pages-sources.md`); the server's `hosting/lib.php` must be the 2026-10-06 version or later to copy them. `site/sky.mjs` (summaries, guards and findings, reusing the app's astronomy, viewing score and pass code), `site/pages-sky.mjs` (pages and SVG figures), `site/sky-family.mjs` and `site/sky-data.mjs` make the sky family of live pages: `/tonights-sky/`, its six city pages and `/iss-today/` (see `docs/sky-pages-sources.md` for what was checked against the USNO tables and what was not). `site/livepages.mjs` lists the live page families and `site/liveregistry.mjs` how each page is read, copied and rendered, by key; `site/events.mjs`, `site/pages-events.mjs` and `site/liveseo.mjs` make the three fleet and events pages (`/starlink-tracker/`, `/natural-disasters-now/`, `/rocket-launches/`, see `docs/events-pages-sources.md`), `site/insight.mjs` the computed findings and `history.json`, and `site/live-pages-js.mjs` the shared progressive-enhancement script `live-pages.js` that `site/build.mjs` writes; `test/live-seo.test.js` holds the Google readiness checklist and the allowlist of the older pages' gaps. `site/live-snapshot.mjs` is the last step of `npm run build:hosting`: it downloads the published `live/` folder and live pages from the `data` branch into `dist/site` with the pull job's checks (path whitelists, sizes and sha256, size limits, all or nothing per part) and never fails the build (see `docs/hosting.md`, "Live snapshot at build time"); `npm run site` alone never downloads. `site/indexnow.mjs` reads the public IndexNow key `site/indexnow.key` (an ownership proof, not a secret); the site build writes it as `<key>.txt` and `hosting/pull.php` pings IndexNow for the live pages that changed (see `hosting/README.md`). `site/pages-about.mjs` and `site/llms.mjs` make the About page and llms.txt; every statement on the About page is traced in `docs/about-sources.md`. `site/home-text.mjs` makes the text section below the home page's first screen, which only the content-site build adds (`wrapApp`), not `template.html`; its statements are traced in `docs/home-sources.md`. The section holds the page's one visible h1 (the loader's h1 goes with the loader), a row of links built from `site/livepages.mjs` (each entry's `name` is its link text) and a strip of six live figures whose values the browser fills from `live/` with the inline script in `site/home-strip.mjs` (pure, unit-tested functions copied into the page by their source text). `site/embed.mjs` (the indexable `/embed/` gallery and snippet maker), `site/embed-widgets.mjs` (the five noindex widget pages under `/embed/<id>/`, each one self-contained file under 30 KB that reads `live/`) and `site/embed-models.mjs` (their pure, unit-tested parts, copied into the pages by source text) are written by the normal site build; sources and what is NOT CONFIRMED in `docs/embed-sources.md`, browser checks in `e2e-embed.mjs`. `site/objects.mjs` (counts by owner and kind, the owner page list, guards), `site/pages-objects.mjs`, `site/objects-family.mjs` (registry entries) and `site/objects-js.mjs` (the pages' search, sort and "Show all" script, pure parts unit tested and copied in by source text) make `/satellites-and-debris-by-country/`, 19 owner pages under `/satellites-by-country/<slug>/` and the objects section of the five country pages, from the collector's daily `satcat` feed (`pipeline/satcat.py`, the whole CelesTrak catalogue) and the satellites feed; sources, accuracy checks and NOT CONFIRMED in `docs/country-objects-sources.md`, browser checks in `e2e-country.mjs`; the server's `hosting/lib.php` must be the 2026-10-07 version or later to copy them. `site/assets/og-image.png` is the share image every page names in `og:image`; `tools/make-og-image.mjs` draws it (run by hand, never by a build) and `site/build.mjs` copies it. `/satellites-near-me/` is a normal static page (`site/pages-near.mjs`, added by `site/near-site.mjs` in `site/build.mjs`) whose tool runs in the browser: `site/near.mjs` (SGP4 pass search and the measured uncertainty table), `site/near-ui.mjs` (options, checks of address and storage values, wording, the map), `site/near-calc.mjs` (the Web Worker; The accuracy measurements are `tools/near-accuracy.mjs` (the model's position) and `tools/near-pass-errors.mjs` (the pass errors the page prints, written to `site/near-errors.mjs`; rerun it on each newer pair of data), with the sample `test/fixtures/near-accuracy.json`; sources and numbers in `docs/satellites-near-me-sources.md`.
