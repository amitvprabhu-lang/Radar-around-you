State of the project when development moved from a cloud session to a local machine, on 2026-10-05. Everything described as done is committed and pushed to `main`. Anything marked NOT CONFIRMED has not been checked.

## What was learned on the real host (2026-10-05)
- A push to `main` triggered a new deployment within seconds to a few minutes (observed twice). Hostinger's panel names for buttons were not verified.
- A redeploy wipes extra files inside `public_html` (a probe file in `public_html/live/` was gone after a deployment). `pull.php` restores the live folder on its next run; tests in `hosting/tests/run.php` cover it. NOT CONFIRMED: whether a deployment also clears folders outside `public_html`.
- Content types: `.json` as `application/json`, `.bin` as `application/octet-stream`, `sw.js` as `application/x-javascript` with a seven day cache lifetime, `manifest.webmanifest` as `text/plain`. NOT CONFIRMED: whether installing the app works with that manifest type (test on a real phone).
- The first deployment stalled at the loader because `index.html` was a bare fragment with no charset (read as windows-1252, which broke a regular expression in the script). Fixed by `asDocument` in `site/build.mjs`; `npm run e2e:site` reproduces the failure on the old output.
- Python is not supported on this plan, even from cron (per Hostinger support). So the collector runs on GitHub Actions and two PHP cron jobs connect it to the site; see `hosting/README.md`.

## Local setup notes
- Needs Node 22, Python 3 and (for `npm run test:hosting`) PHP 8. The unit, pipeline and PHP suites run anywhere.
- **`harness.mjs` line 7 loads Playwright from `/opt/node-tools/node_modules/playwright`, a path that exists only in the cloud container.** Locally, install Playwright and Chromium in the project and change that line to load the project's copy. The launch flags also force a software renderer (`--use-angle=swiftshader`); NOT CONFIRMED that they behave the same on macOS. Test that change against the full browser suites before relying on it.
- The browser tests serve pages at a fake address (`https://radar.test`) through Playwright routes, because the cloud sandbox proxy intercepts localhost. That works anywhere.
- `dist/`, `shots/`, `raw/`, `raw2/` and `preview/` are ignored. `raw3/` is tracked (HYG extract and exoplanet host list, with their licence notes).

## Known flaky checks
Under heavy load or on a slow renderer these timing-based browser checks have failed without a code change: ISS tap, constellation labels, guide text, Under panel text and the clock speed-up measurement. Each was investigated and made more robust (for example the clock check now measures against the clock's own tick times), but there is no guarantee they never flake. A control run on an earlier commit failed some of the same checks, so those were not regressions. If one fails, rerun alone before debugging, and never run two browser suites at once.
