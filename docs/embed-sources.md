# Sources for the embeddable widgets and the /embed/ gallery

Built on 2026-10-07 on the branch `feature/embed-widgets` (from `main` 9955550). Code: `site/embed-models.mjs` (the pure parts: options, snippet, loader, feed to view, the computed sky), `site/embed-widgets.mjs` (the five widget pages, their drawing and page loop), `site/embed.mjs` (the gallery and the writer that `site/build.mjs` calls). Tests: `test/embed.test.js` (unit), `e2e-embed.mjs` (browser, `npm run e2e:embed`). Anything marked NOT CONFIRMED has not been checked.

## What was built and where it lives
- `/embed/` is an ordinary content page (`site/embed.mjs`, `galleryPage`), built by `npm run site` like the guides: in `sitemap.xml` and `llms.txt` (a fixed note, `EMBED_NOTE` in `site/llms.mjs`), indexable unless `SITE_NOINDEX=1`, linked from the home page's live block ("live widgets for your own website", `site/home-text.mjs`).
- `/embed/earthquakes/`, `/embed/aurora/`, `/embed/tropical-storms/`, `/embed/wildfires/`, `/embed/tonights-sky/` are the iframe documents (`widgetHtml`), written by `writeEmbed` from `site/build.mjs` (one import and one call, nothing else changed there). Each is `noindex`, has no canonical link, and is in no sitemap and not in `llms.txt` (the site build's sitemap is made from the page list, and the widget files are not in it; a test checks both files).
- They read the same files as the home page strip and the live pages: `live/manifest.json` (fetched with `no-store`) and the versioned feed files it names, relative to the widget (`../../live/`), the same contract as `site/home-strip.mjs`. The server needs no change: `hosting/lib.php` and `pull.php` copy only `live/` and the live pages, and the widget pages arrive with every deploy because the site build writes them.

## Our choices (OURS, not from any source)
- The coastline in each map widget: the app's coastlines simplified with Douglas-Peucker at 0.4 degrees on a half-degree grid, outlines under 2 degrees across left out (`COAST_EPS`, `COAST_MIN_SPAN`), about 6 KB of text.
- The map box: 58 degrees south to 80 north, widened to take in every point of the data (`wLatBox`), so nothing in the feed is ever left off; the storm map is fitted around the storms and their tracks, with longitudes taken within 180 degrees of the strongest storm so a track across the date line stays in one piece.
- The colours, sizes, animation speeds, the size presets (300 by 220, 400 by 300, 600 by 400, 800 by 450) and the allowed range (280 by 200 to 800 by 600).
- The out-of-date rule: past the live page's limit the widget stops moving, keeps the old picture and says in a yellow line how old the data is; a failed load shows a plain message and no picture. The sky widget's chart is computed and always shows; only its cloud strip depends on the feed, and an out-of-date forecast is not drawn at all.

## The snippet and the credit link
- One `iframe` (`src` on the site's own address from `SITE_URL`, `width`, `height`, a `title`, `loading="lazy"`, `referrerpolicy="strict-origin-when-cross-origin"`, which is stricter than `no-referrer-when-downgrade` and needs nothing from the referrer, and `style="border:0;max-width:100%"`), no `allow` or `sandbox` attribute, plus one line under it: `Live data by <a href="...live page...">Radar Around You</a>`. The anchor text is the site's name, never keywords; nothing is hidden; no `rel` is forced on it, and the gallery says embedders may add `nofollow`.
- Options go in the address (`?theme=light|dark`, `?city=` one of the six ids). `wOptions` takes only values on those lists (anything else falls back to the default), and the page uses the value only as one of those known words (the theme as an attribute value, the city to look up the coordinates and to finish the credit link), never as HTML. `e2e-embed.mjs` sends markup in both options and checks that it reaches neither the page nor the attribute.
- `wSnippet` checks the widget, size, theme and city against the same lists and throws on anything else, and escapes the attributes. The gallery's generator runs the same function (copied by its source text) and builds its preview frame through DOM properties, never through HTML strings.

## Framing
- Nothing in the build blocks framing: no page sets `X-Frame-Options` or `frame-ancestors` (a meta tag cannot set `frame-ancestors` anyway), and the build writes no server configuration. The widget's meta content security policy limits what the widget itself loads, not who may frame it. `test/embed.test.js` checks the widget pages for either header name.
- Seen on the live host on 2026-10-06 18:41 UTC (`curl -I https://zeninnov8.com/right-now/`, before this branch was deployed): no `X-Frame-Options`, and `content-security-policy: upgrade-insecure-requests` only, from `server: hcdn`. Hostinger generates the site's `.htaccess` and regenerates it on every redeploy (`docs/hosting.md`).
- NOT CONFIRMED: that framing works on the live host after this is deployed. Check with `curl -sI https://zeninnov8.com/embed/earthquakes/` (look for `x-frame-options` and `frame-ancestors`) and a real iframe on another site. The build does not write `.htaccess`, so no cache rule for `/embed/` was added; if one is wanted it would have to be a Hostinger setting, which is the owner's call (not needed for the widgets to work).
- The service worker (`public/sw.js`) treats a navigation as network first, so a first-party visit to `/embed/` always gets the current page; in a frame on another site the browser partitions it. NOT CONFIRMED in Safari.

## Known weaknesses
- The widgets read the deploy's `live/` folder: right after a redeploy, until the pull job or the build-time snapshot restores it, they show the plain "could not be loaded" message (the sky chart still works).
- The fire widget downloads `fires.bin` (about 200 KB on 4 October 2026) when its version changes; on a busy host page this is the heaviest widget.
- The sky widget's "well placed" list can differ from the city page's for a planet within about 1 degree of the 15 degree line, and it has no magnitude test (on the nights compared it made no difference). The chart itself draws every planet above the horizon, as a chart should.
- A widget fetches the manifest (a few kilobytes) on each look, even when nothing changed.
- At the smallest sizes the summary is shortened (the full sentence stays in the text alternative), clipped to two lines, and the storm map labels only the strongest storm. Below 360 pixels wide the header drops the words "Data of" and keeps the date, time and zone.
- No live region: the summary changes every minute ("12 minutes ago") and would be read out each time on someone else's page, so a screen reader user reads it on demand.
