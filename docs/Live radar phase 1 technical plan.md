# Live radar: phase 1 technical plan

Draft for review, 4 October 2026. Nothing has been built yet. This plan covers phase 0 (groundwork) and phase 1 (the first public version, "tonight above me"), as recommended in the research report "Live radar around you with hazards". Items marked **(verify)** are things I am not fully certain of and will check against current documentation before writing code.

## 1. Decisions and assumptions

| Topic | Decision | Why |
|---|---|---|
| Domain | New domain (name to be chosen) | You confirmed a new domain |
| Hosting | Cloudflare for everything in phase 1. No WordPress, no AWS | Static files are served free and cached worldwide, scheduled jobs and small server functions run on the same platform, and a traffic spike costs very little |

Ideally ads are paying for it by then |

**How the free plan is made to work:**
- **No heavy processing on our side.** The scheduled jobs copy each source's file into storage almost unchanged. Copying uses very little processing time, so it should stay inside the free plan's 10 ms limit. The format checks run in the browser and in a daily automated test instead.
- **Visitors download data files, not server functions.** The JSON files are served from storage through Cloudflare's cache. Only two small functions (approximate location and planes) count toward the 100,000-a-day limit. If that limit is ever hit, they switch off gracefully: the city search still works and the planes layer hides with a note.
- **Free sources are browser-friendly.** I tested on 4 October 2026: USGS earthquake feeds and NOAA's aurora data allow direct browser access and are cached for 60 seconds. GDACS and NASA EONET also allow it, but EONET sends no-cache headers, so we copy it on a schedule rather than send every visitor to NASA.

**Later phases on this budget:**
- Open-Meteo's paid plan is unlikely to fit, so cloud cover would come from NASA's free satellite imagery (GIBS) instead.
- For ads in Europe and the UK, Google offers its own consent tool inside AdSense; I believe it is free, but verify.
- A small server for heavy map layers would compete with Workers Paid for the same ₹500, so phase 2 and 3 layers should be chosen with that in mind, or wait until ads earn money.

## 3. How the pieces fit

```
Official data sources (USGS, NOAA SWPC, CelesTrak, GDACS, NASA EONET, adsb.lol)
        |
        |  scheduled jobs (Cloudflare Cron Triggers), each on its own timetable
        v
Fetch -> validate -> trim -> write small JSON files to R2 storage
        |                   (keep last good copy; mark stale if a source fails)
        v
Cloudflare CDN caches the JSON files for 30 to 60 seconds
        |
        v
Visitor's phone: static app (HTML + JavaScript + three.js)
  - reads the cached JSON files
  - computes satellite, Moon and planet positions on the phone
  - never sends the visitor's exact location to our server

Small server functions (Cloudflare Workers):
  /api/where        approximate location from the visitor's IP (city level)
  /api/planes       planes near a coarse map cell, cached 10 to 30 seconds
  /api/clouds       cloud forecast for a coarse map cell, cached 1 to 3 hours
  /card/...         share images, generated once per result and cached
  door pages        HTML with the latest live numbers, cached 60 seconds
```

Why this shape: the number of calls to the official sources depends on our schedule, not on how many people visit. A spike of a million visitors mostly hits Cloudflare's cache.

## 4. What phase 1 includes

**The radar (home page): visual first, with every view leading to an action**
1. Opens on an approximate location from the IP address, with no permission prompt. A "Use my exact location" button asks for GPS only when tapped, and a city search box is always available.
2. The first thing on screen is animated, not text. A lightweight animated sky scene loads in under about 50 KB and shows live headline numbers ("14 planes above Berlin right now"). The full 3D globe loads behind it and takes over. The same information also exists as text for screen readers and slow connections, but it is no longer the first impression.
3. The 3D experience flies from space down to the visitor's location and offers four animated lenses (described in section 4a): **Above**, **Tonight**, **Under** and **World**.
4. Every view ends in something the visitor can do, such as "ISS overhead in 3 minutes, look north-west: Guide me / Remind me / Share" (described in section 4b).
5. Every item card shows its source first, plus how fresh the data is ("USGS, updated 2 minutes ago, reviewed").
6. Live counters animate as numbers change. They count real things, never visitors.
7. Sharing: a link with a generated preview image, and a downloadable picture of the visitor's own animated scene, captured as a still frame.
8. Can be added to the home screen as a web app (no push alerts yet).

## 4a. Visual and animation design

The visual principle: **every animation shows real data or real time passing**. Nothing moves just for decoration, and anything illustrative (like a sample meteor streak) is labelled as an illustration.

| Lens | What the visitor sees | Animation |
|---|---|---|
| **Arrival** | Earth from space: real-time day and night line, city lights on the night side, atmosphere glow, live cloud imagery added later | Camera glides from orbit down to the visitor's city, then tilts up into a sky dome above them |
| **Above** | A sky dome over the visitor with compass directions on the horizon. Planes are glowing arrows with short trails showing where they came from. The ISS and bright satellites are moving points with their path drawn across the dome | Everything moves in real time. The ISS path lights up with a countdown when a visible pass is coming |
| **Tonight** | The night sky for this evening: the Moon drawn with its real phase, labelled planets, the aurora ring on the globe as a shimmering curtain built from NOAA's live grid, and meteor shower radiants | A time slider plays the evening forward ("sunset, dark at 19:40, Moon sets 23:10, best window 22:00 to 23:30"). Meteor streaks appear at the expected rate, clearly labelled as an illustration |
| **Under** | A cutaway of the Earth beneath the visitor showing recent earthquakes as glowing points at their real depth | Each quake pulses with a ripple ring at its moment of origin. A 24-hour and 7-day replay plays them in sequence |
| **World** | The full globe with current storms, fires and eruptions from GDACS and NASA EONET | Storms shown as slowly turning spirals along their tracks, fires as soft embers, eruptions as plumes. Calm colours, never alarm red, because these are information, not warnings |

**Look and feel**
- Dark space theme.
- One colour family per lens, so the visitor always knows where they are.
- High contrast text.
- Smooth eased transitions between lenses.
- Optional soft sound, off by default.

**Keeping it smooth on ordinary phones**
- **Quality levels.** The app checks the device and picks high, medium or low quality automatically. The low level uses a flat 2D animated map instead of 3D, so older phones still get a moving, visual experience. A GPU detection library could help here (verify).
- **Lighter images.** Earth textures (for example NASA's Blue Marble and Black Marble images, licence to verify) are compressed and loaded in stages, sharp near the visitor and lower detail elsewhere.
- **Smooth motion.** Target is 60 frames per second on mid-range phones, and never below 30. Animations stop when the tab is hidden, to save battery.
- **Reduced motion.** When the phone's "reduce motion" setting is on, the fly-in becomes a fade and the ripples become static rings.
- **No extra hosting cost.** All drawing happens on the visitor's phone, so rich visuals cost load time, not money. Cloudflare serves static files free.

## 4b. Actions on every screen

| Situation | Action buttons | How it works in phase 1 |
|---|---|---|
| ISS or a bright satellite passing soon | **Guide me**, **Remind me**, **Share** | Guide me turns the phone into a pointer: arrows and a vibration lead you to the right spot in the sky, using the phone's compass after you tap to allow it. Remind me downloads a calendar entry, so no push alerts are needed yet |
| A good night for aurora, planets or meteors | **Best time tonight**, **Remind me** | Combines darkness, Moon brightness, aurora chance and cloud forecast into one recommended viewing window |
| Plane overhead | **Where is it going?** | Shows its route and destination from the live data |
| Earthquake nearby | **Did you feel it?**, **Safety info** | Both link to the official USGS or EMSC report form and official safety guidance. We never collect felt reports ourselves in phase 1 |
| World event | **Official source**, **Follow** | Follow saves the event on the device and highlights it on return visits |
| Any view | **Save this place**, **Compare with another city**, **Share my sky** | Saved places stay on the device. No account is needed |

**Cloud forecast for "Best time tonight":** I would use MET Norway's free weather API. I believe it allows commercial use with attribution and requires an identifying User-Agent, but I will verify this before relying on it. It avoids Open-Meteo's restriction on ad-supported sites.

**Search entry pages (door pages)**, each one the radar opened on a single layer, with live numbers in the page HTML:
- aurora forecast tonight
- meteor shower tonight
- planets visible tonight
- ISS tracker and next pass
- earthquake today
- planes overhead now (small demand, but it shows off the radar)

**Event pages:** one page per earthquake that people likely felt, using a threshold to be decided. The rule is one page per real event, never one page per wording of a search.

**Trust pages:** sources and attributions, methodology, "this is not an official warning service" disclaimer, privacy notice, terms.

**Not in phase 1:** ads, push alerts, accounts, wildfire and storm map layers beyond the World lens icons, lightning, official warnings, tsunamis, floods, air quality, heat, camera-based AR, video export.

## 5. Data jobs

| Layer | Source | How often | Output file | Licence and attribution | Notes |
|---|---|---|---|---|---|
| Earthquakes | USGS GeoJSON summary feeds | Every 1 minute | quakes.json | US public domain; credit USGS | Keep magnitude, depth, place, time, review status and felt reports |
| Aurora | NOAA SWPC OVATION aurora JSON and Kp | Every 5 minutes | aurora.json | US public domain; credit NOAA SWPC | Old solar wind JSON paths now return 404; use the current ones |
| ISS and bright satellites | CelesTrak orbital data in OMM format | Every 2 hours (CelesTrak updates about every 2 hours) | sats.json | Free with citation | CelesTrak firewalls an IP after 50 errors in 2 hours, so the job must back off on errors. New objects have six-digit numbers since July 2026, which the old TLE format cannot hold |
| Planes | adsb.lol live API, point and radius queries | On demand per map cell, cached 10 to 30 seconds | /api/planes response | ODbL 1.0; credit adsb.lol; email them before launch as they ask | Coverage is thin over oceans and parts of Asia, so show the coverage meter |
| World ticker | GDACS API and NASA EONET | Every 10 minutes | world.json | GDACS appears to be CC BY 4.0 via the European Commission notice (verify); EONET has no stated licence and says it is not official (ask NASA or treat as a link-out) | Shown as a list with links to the source, not as warnings |
| Moon and planets | Calculated on the phone with an astronomy library | Live | none | Library licence to check (verify, for example the astronomy-engine package) | No server needed |
| Cloud forecast | MET Norway weather API (verify terms) | Every 1 to 3 hours per coarse map cell, cached | /api/clouds response | Believed free with attribution, including commercial use (verify) | Used only for the "Best time tonight" window |
| Earth images | NASA Blue Marble and Black Marble (verify licence) | Once, at build time | compressed image files | Believed free to use with credit (verify) | Static files, no running cost |
| Meteor showers | Our own small table of shower names, peak dates and typical rates, built from published calendars | Once a year | showers.json | Facts, but cite the calendar used and check its terms (verify) | The International Meteor Organization site was hit by a cyberattack in September 2026, so use a stable source |
| Darkness and twilight | Calculated on the phone | Live | none | None needed | Used for the aurora and pass "can I see it" logic |

Rules every data job follows:
1. **Check before publishing.** On the free plan the job runs light checks only: the response is successful, the format is right and the size is within sensible limits. Full schema checks run in the browser and in the daily automated test. If a check fails, keep the last good file and mark it stale. Never publish broken or empty data.
2. **Freshness stamp.** Every file carries the time it was fetched and the source's own timestamp, and the app shows "updated X minutes ago".
3. **Polite fetching.** Each job sends an identifying User-Agent (the NWS API will require this later), respects rate limits, and backs off after errors.
4. **Trim.** Only the fields the app needs are kept, so files stay small.
5. **Alarm.** If any file goes stale beyond its limit, a monitoring check flags it.

## 6. Front end

- **Stack:** TypeScript, Vite for building, three.js with WebGL2, and satellite.js for orbit maths in a background thread (Web Worker). Whether satellite.js reads OMM data directly needs checking (verify). If it doesn't, we convert OMM fields ourselves and test the conversion.
- **Performance budget:**
  - The first animated scene with live numbers is visible within about 2.5 seconds on a mid-range phone.
  - First download under about 400 KB compressed before the 3D globe starts. Earth images stream in afterwards.
  - Smooth animation: 60 frames per second target, never below 30 on the medium quality level.
  - The globe is drawn with one draw call per object type, animated on the graphics chip.
  - Pixel density is capped on phones.
- **Accessibility:**
  - A full text and list version of every view, reachable in one tap and used by screen readers.
  - Full keyboard control.
  - Never rely on colour alone.
  - Live updates are announced politely to screen readers.
  - Animation stops when the phone's "reduce motion" setting is on.
- **Privacy:**
  - Exact GPS stays on the phone.
  - Map cell requests use coarse cells about 25 km wide (to be tuned), never exact points.
  - No ads or tracking cookies in phase 1, so no consent banner is needed yet.
  - Cloudflare's privacy-friendly analytics only (verify settings).
- **Fallbacks:**
  - If WebGL2 fails, a flat 2D animated map plus the text version.
  - If a data file is stale, the card says so instead of hiding it.

## 7. Testing plan

You asked for unit and regression testing and for nothing else to break. This is a new standalone project in its own repository, so it cannot affect any other repository or anything else. Within the project:

| Test type | What it covers | Tool (verify versions) |
|---|---|---|
| Unit tests | Every data parser using saved real samples from each source; distance and bearing maths; the sun, Moon and planet calculations checked against published almanac values; aurora chance lookup by location; ISS pass prediction checked against reference pass times; the "Best time tonight" window logic; the compass direction and height given by "Guide me"; calendar reminder files; location rounding for privacy | Vitest |
| Animation and quality tests | Frame rate measured on a slowed-down simulated phone for each lens; the right quality level is chosen for each device type; "reduce motion" turns animations off; animations pause when the tab is hidden | Playwright with CPU slowdown and performance traces (verify approach) |
| Contract tests | A daily check that each live source still matches our expected format, so we hear about upstream changes before users do | Vitest plus schema validation (for example zod) |
| Server function tests | Cron jobs, the planes relay, the location endpoint and share cards, run locally against a simulated Cloudflare environment | Wrangler local mode and Cloudflare's Vitest integration (verify package name) |
| End-to-end tests | Load the site on simulated phones with fixed test data: the animated first scene and live numbers appear, globe renders, each lens and action button works, cards show source and freshness, share link works, location button flow works, stale data is labelled | Playwright (Chromium is available in this environment) |
| Visual regression | Screenshots of key views compared with approved versions, so a change can't silently break the look | Playwright screenshot comparison |
| Performance checks | Fail the build if the page gets too slow or too heavy | Lighthouse in the build pipeline (verify setup) |
| Regression gate | Every change runs all of the above automatically before it can go live | GitHub Actions or Cloudflare build pipeline |

## 8. Build order and checkpoints

Each step ends with a check you can see, and I would stop for your review at each checkpoint.

1. **Visual prototype (before anything else):**
   - A working concept page with a snapshot of real data for one city: the fly-in, the Above and Tonight lenses, one "Guide me" and one "Best time tonight" action.
   - It needs no domain or accounts, so it can be built and shared with you for review straight away.
   - **Checkpoint:** you open it on your phone and approve the look, feel and smoothness. This is where the visual direction gets fixed, before money or weeks are spent.
2. **Groundwork:**
   - Domain bought, Cloudflare set up.
   - Empty site live with HTTPS.
   - Repository and automatic test pipeline running.
   - Email sent to adsb.lol.
   - **Checkpoint:** a placeholder page loads on your domain.
3. **Data jobs:**
   - Earthquakes, aurora, satellites, cloud forecast and world ticker fetched, checked and published as files.
   - Monitoring flags stale data.
   - **Checkpoint:** you can open the JSON files and see fresh timestamps.
4. **Live radar:**
   - Location detection and city search.
   - The animated first scene, then the 3D globe with all four lenses, cards, counters and coverage meter.
   - Quality levels and the 2D fallback.
   - **Checkpoint:** smooth on a mid-range Android phone, and works inside the WhatsApp and Instagram browsers.
5. **Actions:**
   - Guide me, Remind me, Best time tonight, Did you feel it, Follow, Save place, Compare.
   - **Checkpoint:** you can go outside and find the ISS using Guide me.
6. **Planes relay:**
   - Coarse-cell planes endpoint with caching.
   - **Checkpoint:** planes appear near you, and data use stays low under a simulated spike.
7. **Door pages, event pages and trust pages:**
   - Each door page opens the animated radar on its own lens.
   - **Checkpoint:** each page shows live numbers in its HTML and passes the performance check.
8. **Sharing and install:**
   - Share images, a still of the visitor's own animated scene, home-screen install.
   - **Checkpoint:** previews look right in WhatsApp and X.
9. **Soft launch:**
   - Share with 20 to 30 people and watch whether they come back and share it.
   - Submit pages to Google Search Console.
   - **Checkpoint:** decide whether phase 2 (hazards) is worth building.
